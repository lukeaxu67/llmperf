八、综合结论（基于 3 轮实验）
--------------------------------------------------------------------------------------------------------------------------------------------

1. TPS 测量可信度评估 (基于 tokens_per_chunk):

   模型/模式              3轮均值 TPS    tok/chunk    3轮均值TPS(含首响)   可信度
   ──────────────────────────────────────────────────────────────────────────────────────────
   M25_normal             172.9          169.3        130.9                低 (粒度粗，TPS 虚高)
   M25_split              315.9          245.4        131.4                低 (粒度粗，TPS 虚高)
   M27_normal             32.5           36.3         26.2                 中 (粒度偏粗)
   M27_split              33.7           35.1         23.4                 中 (粒度偏粗)
   M25HS_normal           55.9           24.2         51.7                 高 (粒度细，测量可靠)
   M25HS_split            55.1           23.2         51.4                 高 (粒度细，测量可靠)
   M27HS_normal           56.3           24.4         52.5                 高 (粒度细，测量可靠)
   M27HS_split            52.9           23.1         48.9                 高 (粒度细，测量可靠)

2. 官方 TPS 标称值验证 (仅看可信测量):

   - M2.7 (normal):       3轮均值 TPS = 32.5  (官方 60 TPS, 达标 54%)
   - M2.7 (split):        3轮均值 TPS = 33.7  (官方 60 TPS, 达标 56%)
   - M2.5-HS (normal):    3轮均值 TPS = 55.9  (官方 100 TPS, 达标 56%)
   - M2.5-HS (split):     3轮均值 TPS = 55.1  (官方 100 TPS, 达标 55%)
   - M2.7-HS (normal):    3轮均值 TPS = 56.3  (官方 100 TPS, 达标 56%)
   - M2.7-HS (split):     3轮均值 TPS = 52.9  (官方 100 TPS, 达标 53%)

   结论: 在 streaming 粒度较细 (tok/chunk < 30) 的模型上，实测 TPS 约为官方标称值的 50-60%。
   这可能因为: a) 测试数据集为长上下文; b) reasoning token 生成更慢; c) 官方值在理想条件下测得。

3. highspeed 加速比验证:

   无首响 TPS:
   - M2.5-HS / M2.5 = 55.9 / 172.9 = 0.32x (官方声称 2x)
     ⚠ M2.5 normal 的 tok/chunk=169 远超可信范围，TPS 虚高，此比较无意义
   - M2.7-HS / M2.7 = 56.3 / 32.5 = 1.73x (官方声称 2x)
     ✓ M2.7 normal tok/chunk=36, M2.7-HS tok/chunk=24, 都在可信范围
     → 实测加速比 1.73x，低于官方 2x

   含首响 TPS:
   - M2.7-HS / M2.7 = 52.5 / 26.2 = 2.00x

   关键发现: highspeed 模型的真正优势是 streaming 粒度更细 (更快的首响, 更好的用户体验),
   而非绝对 TPS 数值提升。

4. reasoning_split 的影响:

   - M2.5 (不可信): split 使 TPS 从 172.9 → 315.9 (tok/chunk 169 → 245)
     这是因为 split 模式下 API 返回更大的 batch，进一步导致测量失真
   - M2.7 (可信): split 使 TPS 从 32.5 → 33.7 (变化约 +3.8%)
     M2.7 的 split 对 TPS 影响不大，tok/chunk 也都在可信范围
   - HS 模型: split 对 TPS 和 tok/chunk 基本无影响

5. 跨轮次一致性 (CV = 变异系数):

   Tag                  CV(TPS)      CV(tok/chunk)   CV(首响ms)     一致性评价       
   ───────────────────────────────────────────────────────────────────────────
   M25_normal           3.6          8.8             0.9          良好          
   M25_split            17.5         9.8             2.1          一般          
   M27_normal           19.3         3.4             9.7          一般          
   M27_split            24.2         17.5            9.4          一般          
   M25HS_normal         2.5          1.6             2.3          良好          
   M25HS_split          2.1          3.2             6.2          良好          
   M27HS_normal         5.2          1.0             15.2         良好          
   M27HS_split          2.4          3.8             9.7          良好          

   结论: 大部分实验的 CV < 15%，说明 3 轮实验结果一致性好，非偶然现象。

6. 最终总结:

   a) MiniMax M2.5 非 highspeed 模式的 streaming 行为异常:
      每个 chunk 包含 ~169 token (应该 ~1-5), 导致 TPS 测量严重失真
      官方 TPS 不可验证 (测量手段失效)

   b) MiniMax M2.7 的 TPS 可信测量:
      实测 ~33 TPS (官方 60 TPS), 约为官方值的 54%

   c) MiniMax highspeed 模型的 TPS:
      实测 ~56-56 TPS (官方 100 TPS), 约为官方值的 56-56%

   d) highspeed 对比非 highspeed (仅 M2.7 可比):
      实测加速比 1.73x, 低于官方 2x
      但 highspeed 模型的首响更稳定、streaming 更平滑 (tok/chunk ~24 vs ~36)

   e) 测试场景说明:
      本实验使用长上下文数据集 (0-64k token), 官方标称值可能在短 prompt 场景下测得
      reasoning token 的生成速度可能慢于 content token
